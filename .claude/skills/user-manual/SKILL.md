# 사용자 매뉴얼 만들기 · 고치기

설명과 보고는 한국어로 한다. 매뉴얼 독자는 **컴퓨터에 익숙하지 않은 일반 사용자**다.

## 원칙: 그림이 먼저, 글은 그림을 따라 읽는 안내
- **기능을 설명할 때는 반드시 화면 캡처를 넣는다.** 글로만 된 기능 설명은 쓰지 않는다. 한 기능에 그림 1장 이상, 창이 길면 위·아래 2장.
- 그림에는 **눌러야 할 곳에 빨간 테두리 + 번호(①②…)** 를 표시하고, 본문 단계·표의 번호와 **똑같이** 맞춘다 (`<span class="n">1</span>`).
- 단계는 "무엇을 누르면 → 무엇이 보인다" 순서로 짧게. 버튼 이름은 화면 글자 그대로 `<span class="btn">저장</span>`.
- 전문 용어 금지: localStorage·패치 포맷·해시 같은 말 대신 "이 브라우저에 저장", "바뀐 내용 묶음" 등.
- 주의할 점은 `.box.warn`, 요령은 `.box.tip` 상자로 눈에 띄게.
- 그림 속 데이터는 **가상의 예시**만 (실제 사람·회사·일정 금지). `scripts/manual/shots.mjs` 의 `demoDb()`.
- 매뉴얼은 **PDF 두 판**으로 낸다: **PC판(A4)** `사용자매뉴얼_PC.pdf`, **모바일판(A5, 휴대폰 화면 캡처)** `사용자매뉴얼_모바일.pdf`.
  PC와 휴대폰은 화면·조작이 다르므로(하단 탭바, 날짜 선택 → 아래 목록, 아래에서 올라오는 창, 회의록 카드) **각 판에는 그 기기 화면만** 넣는다.

## 구성 요소
| 파일 | 역할 |
|---|---|
| `docs/manual/manual.src.html` | **매뉴얼 원본** (두 판 공통). `data-for="pc"` / `data-for="mobile"` 요소는 그 판에만 들어감. 없으면 두 판 모두 |
| `scripts/manual/shots.mjs` | 예시 데이터를 넣은 앱을 PC(1280×800, Chromium)·iPhone 14(WebKit)로 열어 화면을 찍고 번호 표시 → `docs/manual/shots/*.jpg` (휴대폰은 `m-` 로 시작) |
| `scripts/manual/build.mjs` | 캡처 → 원본에 그림 넣기 → 판별로 거르기·장 번호·목차 → PDF 2개. 미리보기 HTML 은 `docs/manual/out/` |
| `사용자매뉴얼_PC.pdf`, `사용자매뉴얼_모바일.pdf` | **결과물 (저장소에 커밋)**. 직접 고치지 않는다 |

```bash
npm run manual                 # 캡처부터 전부 (약 1~2분)
npm run manual -- --no-shots   # 글만 고쳤을 때: 찍어 둔 그림으로 조립만
```
- `docs/manual/shots/`, `docs/manual/out/` 은 git 에 넣지 않는다 (매번 다시 만듦).
- 배포 준비(`npm run release`)가 매뉴얼을 새 버전으로 다시 만든다. 표지·그림 속 버전이 앱 버전과 같아진다.

## 절차

### 1. 무엇이 바뀌었나 확인
- `git diff` 로 앱(`project-calendar-app.html`)에서 바뀐 화면·버튼·문구·흐름을 찾는다. 새 기능이면 장(section)이나 소제목을 추가, 바뀐 화면이면 해당 캡처를 다시 찍는다.
- PC와 휴대폰 중 **어느 쪽 화면이 바뀌었는지** 본다. 둘 다면 두 판 모두 고친다.

### 2. 캡처 추가·수정 (`scripts/manual/shots.mjs`)
- PC 캡처는 PC 블록에, 휴대폰 캡처는 `/* 휴대폰 */` 블록에 `m-이름` 으로 추가한다.
- 순서: 화면을 그 상태로 만든다(클릭·입력) → `mark(page, [{ loc, n, side? }])` 로 번호 표시 → `shot(page, "이름", 영역?)`.
  - 영역을 주면 그 부분만(창이면 `modal(p)`), 안 주면 화면 전체. 휴대폰은 보통 화면 전체.
  - 번호 배지가 겹치면 `side: "right"`. 화면 가장자리 요소는 배지가 자동으로 안쪽에 그려진다.
  - 넓은 패널은 `narrow(page, "#tab-x .panel")` 로 캡처할 때만 폭을 줄여 종이에서 글씨가 작아지지 않게 한다 (끝나면 `narrow(page, "", false)`).
  - 휴대폰에서 창이 길면 `sheetBottom(m)` 으로 아래까지 밀어 올린 화면을 따로 찍는다. 화면 밖 요소는 `into(loc)` 로 스크롤.
- 필요한 데이터는 `demoDb()` 에 가상의 예시로 추가한다. 시계는 2026-11-24(화) 10:00 고정.
- 디자인은 인쇄용으로 '화이트'(`THEME`)로 찍는다. 앱 자체(HTML)를 매뉴얼 때문에 바꾸지 않는다. 캡처 중 화면 오류를 발견하면 앱을 고치되 E2E 를 함께 돌린다.

### 3. 본문 수정 (`docs/manual/manual.src.html`)
- 그림: `<figure data-shot="이름"><figcaption>설명</figcaption></figure>`. 휴대폰 그림은 `class="phone"`, 좁은 창은 `class="half"`.
- 판 구분: 그 판에만 필요한 문단·그림·표에 `data-for="pc"` / `data-for="mobile"`. 공통 문장은 표시 없이 한 번만.
- **장 번호는 자동**이라 다른 장을 가리킬 때 번호 대신 이름으로 쓴다 ('취소와 연기' 장).
- 그림 속 번호와 본문 번호가 1:1 로 맞는지 확인한다 (그림에 없는 번호를 본문에 쓰지 않는다).

### 4. 만들고 눈으로 확인 (필수)
```bash
npm run manual
```
- 출력에 "매뉴얼에서 쓰지 않는 캡처"가 나오면 본문에 넣거나 캡처를 지운다. "캡처 이미지가 없습니다"면 shots.mjs 에 추가한다.
- **새로 찍거나 바뀐 그림은 Read 로 직접 열어 본다**: 번호 위치가 맞는지, 배지가 글자를 가리지 않는지, 창이 잘리지 않았는지.
- **PDF 쪽도 확인한다**: 이 PC 에는 poppler 가 없으므로 macOS PDFKit 으로 쪽 이미지를 만들어 Read 로 본다
  (예: 스크래치패드에 `PDFKit` 으로 `page.thumbnail(of:for:)` → jpg 저장하는 swift 스크립트). 그림이 쪽 경계에서 잘리거나, 글씨가 너무 작거나, 빈 쪽이 생기지 않았는지 본다.

### 5. 커밋
- 원본·스크립트·PDF 2개를 함께 커밋한다. 매뉴얼만 바뀐 커밋은 E2E 대상이 아니다 (앱을 고쳤다면 E2E 가 돈다).
- 보고: 바뀐 장·그림 목록, 두 판의 쪽수·용량, 확인하지 못한 부분(예: 실제 기기에서만 보이는 동작).

## 금지
- PDF 를 직접 편집하거나 손으로 찍은 스크린샷을 넣지 않는다 (다음 버전에서 낡은 그림이 됨). 반드시 shots.mjs 로 재현 가능하게.
- 실제 사용자 데이터·사진(사용자가 보낸 스크린샷 등)을 매뉴얼이나 저장소에 넣지 않는다.
- 그림 없이 글로만 기능을 설명하지 않는다.
